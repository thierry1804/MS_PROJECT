<objective>
## Goal
Implement client-side dialogue orchestration: session state machine (gathering → preview → executed/cancelled), slot filling from user messages and portfolio context, and deterministic question policies per intent.

## Purpose
Enables the copilot to ask the right questions when information is missing — core PMO UX requirement — without waiting for UI or LLM plans.

## Output
- `session.ts` — createSession, applyUserMessage, applySlotAnswer, transitionToPreview, cancel, execute
- `slot-filler.ts` — extractSlotsFromText, inferFromPortfolio, applyDisambiguations
- `question-policy.ts` — buildQuestionsForIntent (generalize risk-assist questions.ts pattern)
- Vitest tests for slot filling and question ordering
</objective>

<acceptance_criteria>

## AC-1: Session state machine
```gherkin
Given a new CopilotSession
When user sends first message with partial intent
Then phase remains "gathering" and pendingQuestions is populated
When all required slots filled
Then phase transitions to "preview"
When user confirms preview
Then phase becomes "executed"
When user cancels at preview
Then phase becomes "cancelled" with no store mutation
```

## AC-2: Slot extraction from natural language
```gherkin
Given message "Crée un projet CRM Migration budget 120000 chef Dupont"
When extractSlotsFromText is called for intent createProject
Then slots name, budget, manager are extracted
And budget parsed as number 120000
```

## AC-3: Portfolio inference
```gherkin
Given portfolio with one active project "Alpha" and user message "ajoute un risque fournisseur"
When inferFromPortfolio runs without projectId slot
Then projectId is suggested as choice question with Alpha as first option if only one match
Given memory disambiguation "projet en retard" → projectId X with count 3
Then projectId defaults to X before asking
```

## AC-4: Question policy for pipeline gates
```gherkin
Given intent moveDemand with stage "approuvee"
When buildQuestionsForIntent runs
Then questions include approver (text) and criteria (checklist from GATE_CRITERIA.approuvee)
And max 3 questions returned per call
```
