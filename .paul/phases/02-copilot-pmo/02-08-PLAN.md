<acceptance_criteria>

## AC-1: addTask
```gherkin
Given project with WBS and slots { projectId, name: "Recette UAT", duration: 5, parentTaskId? }
When addTask executes
Then new leaf task appended with correct duration and name
And schedule recalculates via store autosave
```

## AC-2: updateTask
```gherkin
Given task "Conception" identified by name match
When updateTask with { duration: 10 } or { percentComplete: 50 }
Then task patched via store.updateTask
```

## AC-3: addDependency
```gherkin
Given predecessor and successor resolved by name
When addDependency with type FS and lagDays: 2
Then dependency added if no cycle (store handles cycle detection)
```

## AC-4: captureBaseline
```gherkin
Given project with schedule
When captureBaseline executes
Then baseline captured same as ProjectView toolbar action
```

## AC-5: shiftTasks with impact preview
```gherkin
Given task "Recette UAT" and shiftDays: 10
When buildPlanningImpactPreview runs
Then preview lists count of successor tasks whose dates change
When user confirms shiftTasks
Then updateTask applies SNET or duration/date patch per store conventions
```

## AC-6: Task disambiguation
```gherkin
Given message "retarde la recette" with 2 tasks containing "recette" in project
When resolveTaskByName returns multiple matches
Then choice question lists matching tasks with WBS and dates
```
