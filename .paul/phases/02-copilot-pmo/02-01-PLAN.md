<objective>
## Goal
Create the foundational copilot layer: typed intents, slot definitions, action registry mapping `{ intent, params }` to Zustand store methods, and a preview builder for confirmation before mutations.

## Purpose
All downstream copilot plans (dialogue engine, UI, LLM API) depend on a stable, testable action registry that reuses existing store validations without duplicating business logic.

## Output
- `apps/web/src/copilot/types.ts` — CopilotIntent, SlotDef, CopilotQuestion, CopilotSession, ActionPreview
- `apps/web/src/copilot/registry.ts` — INTENT_REGISTRY, getMissingSlots(), executeAction()
- `apps/web/src/copilot/preview.ts` — buildPreview(intent, slots) → human-readable recap
- `apps/web/src/copilot/index.ts` — barrel exports
- `apps/web/src/copilot/registry.test.ts` — Vitest for slot validation and preview
</objective>

<acceptance_criteria>

## AC-1: Intent registry covers core store actions
```gherkin
Given the action registry is loaded
When listing registered intents
Then at minimum these intents exist with slot schemas:
  createProject, updateProject, deleteProject,
  addRaidItem, updateRaidItem, removeRaidItem,
  addDemand, moveDemand, convertDemand, deleteDemand,
  addTask, updateTask, deleteTask, addDependency, removeDependency,
  captureBaseline, logTime, addResource, updateResource
And each intent declares required vs optional slots
```

## AC-2: Missing slot detection
```gherkin
Given intent createProject with only slot name="CRM Migration"
When getMissingSlots(intent, slots) is called
Then it returns manager and budget as pending (in defined order)
And optional slots (description, strategicAxis) are not in pending unless marked required
```

## AC-3: Preview before execution
```gherkin
Given intent moveDemand with slots { demandId, stage: "approuvee", approver: "Martin", criteria: [...] }
When buildPreview is called
Then it returns a French summary listing demand title, target stage, approver
And requiresConfirmation is true for deleteProject, deleteDemand, resetPortfolio, removeRaidItem
```

## AC-4: Execute delegates to store
```gherkin
Given a mock store and intent createProject with complete slots
When executeAction(store, intent, slots) is called
Then store.createProject is invoked once with equivalent ProjectDraft
And no direct PUT /api/portfolio call is made from registry
```
