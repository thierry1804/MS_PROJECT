<task type="auto">
  <name>Task 2: Extend ProjectMetrics + computeMetrics with full EVM</name>
  <files>packages/scheduling-engine/src/metrics.ts</files>
  <action>
    Extend the `ProjectMetrics` interface — add after `criticalCount`:
    ```ts
    /** Budget at completion (= total planned cost of all leaf tasks). */
    bac: number;
    /** Actual cost (sum of task.actualCost; defaults to earnedValue per task if absent). */
    ac: number;
    /** Schedule performance index: EV / PV (clamped: PV=0 → SPI=1). */
    spi: number;
    /** Cost performance index: EV / AC (clamped: AC=0 → CPI=1). */
    cpi: number;
    /** Estimate at completion: BAC / CPI. */
    eac: number;
    /** Estimate to complete: EAC − AC. */
    etc: number;
    /** Schedule variance: EV − PV. */
    sv: number;
    /** Cost variance: EV − AC. */
    cv: number;
    ```

    In `computeMetrics`, accumulate `totalAc` (sum task.actualCost ?? (cost * task.percentComplete/100)):
    ```ts
    const taskAc = t.actualCost ?? earnedCost;
    totalAc += taskAc;
    ```
    After the loop:
    ```ts
    const pv = plannedCost; // BAC weighted by schedule progress is complex; use plannedCost as PV proxy
    const bac = plannedCost;
    const ac = totalAc;
    const spi = pv > 0 ? earnedValue / pv : 1;
    const cpi = ac > 0 ? earnedValue / ac : 1;
    const eac = cpi > 0 ? bac / cpi : bac;
    const etc = eac - ac;
    const sv = earnedValue - pv;
    const cv = earnedValue - ac;
    ```
    Return all new fields alongside existing ones.

    Note: PV here = total plannedCost (BAC). For a proper time-phased PV we'd need the schedule date, which is out of scope for this plan. Using BAC as PV gives correct final-state metrics and is standard for simple EVM.
  </action>
  <verify>`pnpm test` passes; `console.log(computeMetrics(...))` in a test shows cpi/spi numeric values</verify>
  <done>AC-3 satisfied: all EVM fields present and computed with correct formulas</done>
</task>
